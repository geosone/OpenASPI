# Native ATAPI LS-120 test

The local 86Box development build already contains an LS-120 model. The
separate 6.0 backport enables the corresponding drive type, validates native
120-MB images, supplies the LS-120 inquiry identity and reports its maximum
capacity when empty. It reuses the existing removable-disk command engine.
The existing ZIP drive type numbers and accepted ZIP image sizes stay intact.

## Portage 6.0 backport

The additional patch is installed at:

```text
/etc/portage/patches/app-emulation/86Box-6.0/0002-rdisk-enable-native-ATAPI-LS-120-media.patch
```

It is separate from the existing CD catalog patch. A merge that has already
passed the user-patch stage will need another merge to pick up this patch:

```sh
emerge -1av =app-emulation/86Box-6.0
```

The test does not run emerge or replace the system binary. The local 6.0
build is `../86Box-6.0-upc/build-upc/src/86Box`. In the removable-drive settings,
select `IMATION SUPERDISK 120 ATAPI`, with ATAPI on secondary master.

The LS-120 type number is 3 in this limited 6.0 backport and 7 in the tested
development build. Do not copy the numeric drive-type setting between these
versions without selecting the correct model again in the settings dialog.

## Repeatable test

For the development build with its automation interface:

```sh
bash tests/dos_86box_ls120.sh
```

For the patched 6.0 build, which lacks that interface:

```sh
LEGACY86BOX=1 BOX="$PWD/../86Box-6.0-upc/build-upc/src/86Box" \
  OUT="$PWD/build/86box-ls120-6.0" bash tests/dos_86box_ls120.sh
```

Override `ROMDIR` to use an existing local 86Box ROM directory. The test uses
Xvfb; the 6.0 variant additionally uses xdotool and libX11. ROMs are not
distributed. A SvarDOS boot fixture is reused from `build/dos-cda/boot.img`,
or prepared by the existing CD smoke-test script if absent.

Each run creates a fresh, partitionless FAT16 image with 246,528 sectors of
512 bytes (126,222,336 bytes), then boots AHCIASPI and ASPIFDD. ASPIFDD assigns
the emulated LS-120 to C:. This is a native ATAPI device, distinct from the
USB device named SUPERDISK in the QEMU block test.

The guest scans the device, reads a known text file and copies a 100,000-byte
file through DOS to the boot disk and back, with VERIFY OFF and VERIFY ON.
After normal VM shutdown the host compares both resulting files byte for
byte and checks the FAT filesystem. Logs and disposable images remain under
`build/86box-ls120` or the selected `OUT` directory. Both the development and
patched 6.0 builds passed this sequence.

This establishes native 120-MB read/write operation. Ordinary 720-KB and
1.44-MB media, original MKELS120 formatting commands, write protection,
media swaps and DEVICEHIGH operation of ASPIFDD are not qualified by this
test. In particular, this backport currently accepts only the native 120-MB
size in the LS-120 drive.
